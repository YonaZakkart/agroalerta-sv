6-0 — Base de Angular
---------------------

Rama feat/6-0-base-angular (Parte 6, Punto 0 del Mapa v2: Base de Angular)
Responsable: Yona
Fecha: 31 de octubre de 2026

Contexto: el frontend era el proyecto generado con Angular CLI (22.1.8), con el placeholder de bienvenida y sin rutas. El Mapa v2 pide una base común que se mergee primero y rápido, porque toca los archivos compartidos del frontend (app.routes, app.config, styles.css y package.json). Esta rama NO se conecta al backend.

Alcance acordado (reduce el del Mapa v2, ver "Cambios respecto al Mapa v2"): estructura, estilos, rutas, layout y vistas vacías, sin ninguna función.

Qué se hizo:
- app.html pasa a contener solo <router-outlet />; app.ts queda con el componente raíz mínimo (App, con RouterOutlet). Se eliminó el placeholder de Angular y la señal "title".
- app.spec.ts: se reemplazó la prueba, que buscaba el texto "Hello, frontend" y habría fallado, por una prueba de creación del componente.
- index.html: idioma es, título "AgroAlerta Morazán", meta viewport y theme-color (#059669), fuente Plus Jakarta Sans (Google Fonts) e iconos Font Awesome 6.4.0 (cdnjs), ambos por CDN.
- styles.css: variables CSS (colores, radios, sombras, fuente) tomadas de login_base.html y dashboard_base.html; reset básico; estilos de formulario compartidos (.form-group, label, input, select, .form-grid, .btn-primary), con campos de 44 px de alto mínimo y fuente de 16 px para evitar el zoom automático en iOS.
- app.routes.ts: /login y /registro (carga diferida, con título), y un grupo con el layout Shell que contiene /dashboard; "" redirige a /dashboard y "**" a "". Sin guard.
- Componentes nuevos (ng generate, sin pruebas): layout/auth-shell, layout/shell, pages/login, pages/registro y pages/dashboard.
- AuthShell: panel de acceso con pestañas Iniciar sesión / Registrarse (routerLink con routerLinkActive) y proyección de contenido (ng-content).
- Login y Registro: formularios con los campos de la referencia visual (registro: nombres, apellidos, correo, contraseña, DUI, distrito), con submit que solo hace preventDefault.
- Shell: sidebar y encabezado con estado de componente (signal menuAbierto) en lugar del "checkbox hack" del HTML base. Cajón con fondo oscurecido en móvil; columna fija desde 1024 px. Historial, Clima Zonal y Configuración aparecen deshabilitados (aria-disabled) porque aún no hay vistas.
- Dashboard: tarjeta vacía con texto indicativo.

Decisiones de diseño:
- Los HTML base son solo referencia visual (colores, tipografía, jerarquía). Estructura y comportamiento responsive son propios, porque los HTML base no son responsive.
- Mobile-first: el CSS base es el de móvil y se amplía con min-width (600 px formularios en dos columnas; 900 px panel de acceso con lado visual; 1024 px barra lateral fija). Los HTML base usaban max-width.
- Se quitó la foto de Unsplash del lado visual del login y se dejó solo el degradado: evita una dependencia externa de peso en la demo.
- Texto del lado visual: "viabilidad de suelo" pasa a "viabilidad de cultivo", que es lo que muestran los datos de CENTA.
- Campo distrito del registro: texto libre sin valor precargado (el HTML base traía "Chilanga"). Si la 6-A lo convierte en select, hace falta el endpoint público de distritos (C1 del Mapa v2).
- Iconos por CDN en lugar de dependencia npm: no toca package.json ni el lock. La demo requiere internet (confirmado sin problema por el equipo).
- Foco y accesibilidad básica: botones de menú con aria-label y aria-expanded; el cajón cerrado usa visibility:hidden para que el teclado no entre en él.

Cambios respecto al Mapa v2 (documentados según reglas del proyecto):
- 6-0 del Mapa v2 incluía servicio de autenticación con almacenamiento del token, interceptor HTTP, guard de rutas, URL del API (proxy o CORS) y modelos TypeScript de los contratos. Se aplazan a la 6-A, para conectar con el backend solo cuando exista una pantalla que lo use.
- Criterio del Mapa v2 "ng build sin errores, ruta protegida redirige al login, interceptor agrega el encabezado": se cumple solo el primer punto; los otros dos pasan a la 6-A.
- Decisión sobre proxy o CORS: la presentación será en local (confirmado), por lo que se prevé proxy de desarrollo de Angular; se decide en la 6-A.

Qué se eliminó: el placeholder de bienvenida de Angular (app.html) y la señal title de app.ts.
Qué se agregó: layout/shell, layout/auth-shell, pages/login, pages/registro, pages/dashboard (cada uno con .ts, .html y .css).
Dependencias nuevas: ninguna. package.json y package-lock.json no se tocaron [VERIFICAR con git status antes del commit; un npm install previo pudo modificar el lock y debía descartarse].
